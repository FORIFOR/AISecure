# AI利用・情報持ち出し・VPN侵入に対する防御の実装境界

確認日: 2026-09-16。状態: **実接続前の初期ガード／本番防御の完成版ではない**。

## 今回追加したもの

`aisecure/preflight.py` は、信頼されたアプリケーションアダプターが提出する
テキスト送信・ツール操作の事前検査ライブラリである。既存のログ相関・承認・
レスポンダーを置き換えない。公開サイトと既存ダッシュボードの動作は変更しない。

- 許可は管理者設定の「操作 × 固定HTTPS URL × ツール × データ分類」の完全一致。
  既定は許可なし。URLの部分一致、自己申告の `approved`、LLMによる上書きは不可。
- 機密・持出禁止の分類、対応する秘密情報パターンは拒否する。
  未分類、個人情報に似たパターン、高影響操作は保留する。保留も実行しない。
- `guarded_call()` は allow 以外で通信処理を呼ばない。allow の場合は同一の不変
  Requestをアダプターの通信処理へ渡す。外部送信を行う通信処理自体は同梱しない。
- 入力の不正・上限超過・未対応フィールドは拒否。説明と例外に本文・送信先を出さない。
- 日本語の理由、根拠ルール、証跡ID、検査範囲、未実行状態を返す。
- `--history` は提出済み履歴を再検査するが、実送信・漏えいの有無は確認しない。
- `Decision.finding()` は既存 `Explainer` が受け取れる、本文を含まない事実を返す。
  この追加ガード自体は生成AIを呼ばず、ダッシュボードへの自動表示も未接続。

## 使用方法

リポジトリのルートで、管理者だけが変更できる `policy.json` を用意する。
例示の `.example` は架空の送信先であり、そのまま通信先として使用しない。

```json
{"grants":[{"action":"ai.prompt","destination":"https://approved.example/v1/text","data_classes":["public"]}]}
```

```bash
python -m aisecure.preflight --policy policy.json <<'JSON'
{"event_id":"EV-1","action":"ai.prompt","destination":"https://approved.example/v1/text","text":"公開済みの商品説明です。","data_class":"public"}
JSON
```

終了コードは `0=ポリシー検査通過`、`2=拒否または保留`、`3=入力・設定不正`。
**CLIは検査のみであり、終了コード2は実ネットワークの遮断実績ではない。**
入力JSON配列を標準入力へ渡して `--history` を指定すると履歴を検査できる。
履歴の `execution_state` は必ず `historical_execution_unknown` と表示する。

アプリへの接続では、通信の後ではなく直前にラッパーを置く。

```python
from aisecure.preflight import guarded_call

# request / policy / fixed_transport は信頼されたアダプターが構成する。
# 拒否例外を捕捉して通常の通信へフォールバックしてはいけない。
result = guarded_call(request, policy, fixed_transport)
```

`Request` の必須項目は `event_id` (`EV-` + 1〜12桁)、`action`、`destination`、`text`。
`data_class` の省略は `unknown`。`agent.*` では管理されたレジストリの `tool` が必須。
テキストはUTF-8で256 KiBまで、CLI全体は2 MiBまで、履歴は1000件まで。
`ai.prompt`、`storage.upload`、`agent.read` だけ許可を登録できる。
`agent.execute`、`agent.delete`、`agent.share`、`agent.send` はこの初期版では常に保留する。
別の認証済み・内容固定・期限付き承認経路の設計を経ずに通してはいけない。

## 防御と呼べるための必須条件

1. **信頼境界**: policy、分類、操作の意味、ツール台帳は管理者・信頼された収集器が
   管理する。モデルが `public` / `agent.read` と申告しても採用しない。同一プロセスを
   攻撃者が変更できる場合、このPythonライブラリは境界にならない。
2. **実データとの一致**: 検査するtextは、実際に送るすべての本文の最終テキストと一致
   させる。添付・メモリー・検索結果・HTTPヘッダー・クエリ・別の送信経路を隠して
   追加してはいけない。モデル出力による宛先や本文の差し替えは再検査する。
3. **通信側の制約**: 固定通信処理はTLS検証、リダイレクト拒否、適切なDNS/IP検証、
   Proxy環境変数の扱い、タイムアウト・再試行の制限を実装する。認証情報は
   Secret Manager等から通信処理内だけに注入し、モデル・本文・ログには渡さない。
   同じホストでも個人テナントと社内テナントを区別する仕組みが別途必要。
4. **迂回不可**: 端末・ネットワーク側で直接通信を制限する。ブラウザ拡張やIDEフック
   だけでは、他ブラウザ・curl・別プロセス・USB等を制御できない。モデルがガードを
   呼ぶかどうかを選べる構成は防御境界ではない。
5. **実証**: 拒否したペイロードが外部の試験受信器に届かないことを、認可された
   検証環境で独立した通信記録と受信記録から確認する。Mock試験だけでは足りない。

## 明示的な未対応・限界

これはEDR、VPN装置、ブラウザ拡張、企業DLP、AI APIリバースプロキシではない。
インストールだけで端末・組織を常時保護しない。既存ログの自動収集も追加していない。

秘密情報・メール・電話の検出は限定された正規表現であり、完全な個人情報分類器ではない。
氏名・住所のみの名簿、独自形式のトークン、画像、PDF、音声、暗号化・圧縮・base64、
分割された情報、間接的な漏えいを網羅しない。検出しないことは安全の証明にならない。
正常なメールアドレス等を保留する誤検知もある。機密ラベルは信頼された分類器・台帳から
与える必要がある。危険な文面を発見する汎用プロンプトインジェクション検出器でもない。

承認済みサーバーの侵害、認証情報盗難、通信先の保持・学習設定、同一ドメイン内の
個人アカウント利用、ガード外のネットワーク、OS管理者権限はこのモジュールでは防げない。
送信の成功・失敗、外部処理の完了、封じ込め、既存漏えいの否定を確定しない。

## 事件を基準とした製品化要件（未実装部分を含む）

### ドコモ: 委託先から個人ストレージへ持ち出された型

基準にしたのは2023年7月21日公表のぷらら・ひかりTV事案である。ドコモは、
元派遣社員が業務用PCから個人契約の外部ストレージへ2023年3月30日に持ち出し、
対象は約596万件だったと公表している。[S1]
別のドコモ／NTTの事案と同一視しない。

必要な防御は、機密分類、委託先・端末・利用者の権限管理、個人テナントへの送信制限、
端末DLPによるファイル持出し・USB制御、業務上必要な取得範囲の制限である。
正常ログインからの不正もあり得るため、VPN侵害や未承認ログインとの相関を必須条件に
してはいけない。単一ファイル／少量ずつの持ち出しも試験対象にする。
今回のガードは、接続されたテキスト送信経路だけを拒否できる部品である。
元事件の防止を実証したものではなく、端末DLP・通信経路の強制適用は未実装。

### デジタル庁: VPNの既知脆弱性を起点とする型

2026年9月11日公表、同月12日更新の公式資料では、6月25日に保守アカウントによる
大量参照を検知、7月9日にVPN脆弱性を悪用した不正アクセスと判明したとしている。
脆弱性は公表済み・当初の深刻度Medium、修正適用前に悪用された。具体的CVEや機器は
非公表であり、架空のCVEや点数を元事件の値として提示しない。[S2][S3]

既存AS-001/004は入力された公開機器・特権・大量参照を関連付けるが、以下が必要。

- ベンダー・製品・正確な版数・公開面・管理者・取得日時を実機から読み取り専用で取得。
- ベンダー情報とKEV等を更新し、該当版を照合。KEV未掲載だけで安全と判定しない。[S4]
- CVSSだけでなく、外部公開・認証前攻撃・機密到達性・悪用状況・パッチ期限で優先付け。
- パッチ完了までの管理接続制限、保守権限の短期化、セグメント分離を機器側で強制。
- 不審セッションの失効、通信隔離、認証情報更新、必要に応じた再構築を、承認された
  レスポンダーで実施。実行APIの成功だけではなく実機再確認と独立ログで検証。
- MFAだけで脆弱性悪用・セッション窃取を防げると表示しない。

今回の変更にVPNアダプター、CVE照合器、パッチ適用、ファイアウォール制御は含まれない。

## 次の実装単位

| 優先 | 実装 | 完了条件 |
|---|---|---|
| P0 | 1つの実AI API経路をガードへ強制接続 | 拒否時に試験受信器への対象本文到達0件。通信失敗・再試行でも迂回なし |
| P0 | 端末／クラウドDLP連携 | 私物テナント、正常ログイン、少量分割、USB等で経路別に防御結果を検証 |
| P0 | 管理対象VPN/IdPの読み取りアダプター | 型番・版数・設定・期限・権限の確認根拠を表示。未知はunknown |
| P0 | 改修・封じ込めアダプター | 二者承認、対象固定、冪等性、実状態の確認、復旧試験 |
| P1 | AI/MCP/Skills監査 | ツール定義・権限・実行内容・供給元・変更を照合。権限拡大で再承認 |
| P1 | 平易なAI調査画面 | 事実・仮説・不明・根拠・推奨操作・業務影響・監視範囲を分離 |

AI/MCP/Skillsの基準はOWASPのLLM/Agentic/Skills資料とMCP公式セキュリティ指針を
定期的に確認する。[S5][S6][S7][S8] OAuthのaudience検証、最小権限、トークンの
不適切な引き渡し禁止等はアダプターで実装する。更新をAIの記憶だけに依存しない。
外部フィードやSkills自体も信頼済み命令ではなく未信頼データとして扱う。

## 表示仕様

画面は「現在の危険」「止めた操作」「過去の履歴」「監視できていない範囲」に分ける。
現時点では未実装の表示仕様である。各項目は次の順に説明する。

1. 起きたこと／止めようとしていること。
2. 危険な理由と根拠イベント、観測時刻、収集元。
3. 確認済み事実と未確認事項。悪意や漏えいを推測で断定しない。
4. 次の推奨操作、対象、必要承認、止まる業務、復旧方法。
5. 「助言のみ」「接続済み」「実行要求済み」「実機確認済み」の区別。

生成AIは仮名化・最小化済みの根拠から補助説明する。生の秘密情報は渡さない。
説明AIに通信・実行・承認・ポリシー編集権限を与えない。
「スキャン結果0件」と「全体が安全」、「監査API成功」と「侵入防止済み」を区別する。
