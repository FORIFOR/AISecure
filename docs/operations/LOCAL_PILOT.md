# 最初のローカル評価: 導入実績を作るための受け入れ手順

状態: **評価候補を準備中。顧客への導入・受け入れ・有償契約は未成立。**
この手順は外部送信や本番保護を許可するものではない。
[企業向けの未達条件](../security/ENTERPRISE_READINESS.md)はそのまま残る。

## 最小の対象と終了条件

1社・1人の担当者・1台の許可済みローカル環境で、「AIへ渡す前に資料を点検し、
検査範囲と未検査を理解して記録できるか」を評価する。5営業日を上限の目安に、
最初は合成データのみ。APIキー、IdP/VPN接続、ブラウザー拡張、外部AI送信、
既存DLPの置き換えを含めない。価格・実施日・対応時間は別途合意する。

- 提供側の目安: 準備・起動90分、評価2時間、説明・報告1時間、問い合わせ1時間
- 最大1件の範囲内の改善まで。上限を超える原因や必要権限が分かったら中断し再合意
- 24時間対応・本番SLA・監視の継続・セキュリティ保証はこの評価に含まない
- 成果は「合格/不合格」だけでなく、見逃した種類、不要な確認作業、未検査の割合、
  次に進める条件を示す。見逃しを測れたことと保護性能の合格は別である

## 開始前に責任者と固定する記録

記録は顧客の手元で保管する。下記の未記入項目を合格扱いにしない。

- 対象業務、責任者、操作者、実施日、許可した端末とOS/Python、候補commit
- データの所有者と範囲、保存先・保持期限、共有する結果とその宛先
- 必須カテゴリ、陽性/陰性の件数、カテゴリ別の許容見逃し数・誤検知数
- 許容する手動確認時間、未検査/読み取り不能の割合、セットアップ時間の上限
- 中止連絡先と利用を止める手順。担当者が使い方と限界を説明できること

基準は結果を見る前に固定する。未達後に分母・ラベル・基準を変えて合格にしない。
現行の公開60件コーパスの再現率は0.30で、機密情報一般を止める用途には不足する。
この評価では検知パターンを変えない。改善するなら別revisionで同じコーパスを再測定し、
追加ケースの結果は別に提示する。機密が1件も通らないことが必須なら、その要件を
満たすまで実業務には進めない。

## 1. 合成データで再現する

[最初の成功](../FIRST_PROOF.md)に従い、依存物を準備した許可済み環境で起動する。
レビューしたcommitと差分なしを確認し、既存の必須テストとローカルチェックを実行する。

```sh
python tools/run_full_tests.py --report /tmp/aisecure-full-new.json
python tools/check_control.py --output /tmp/aisecure-control-new.json
python -m tools.measure_detection --out /tmp/aisecure-detection-new.json
```

依存不足・skipはBLOCKED。測定コマンドの終了コード0は「測定完了」であり、
受け入れや安全性の合格ではない。外部接続なしのテストは実機保護を証明しない。
これらのコマンド自体はOSの通信隔離機能ではない。

顧客の情報の「型」に合わせて最低30件程度の合成テキスト例を用意する。
陽性と陰性の両方、紛らわしい陰性、必須カテゴリの見逃し例を含める。
この件数は初期の問題発見用で、実運用精度を推定する統計的保証ではない。
文書検査とは別の測定であり、テキストの再現率をPDF/Officeの抽出性能に転用しない。

```sh
python -m tools.measure_detection --corpus pilot-synthetic.jsonl --out pilot-before-new.json
```

JSONLの各行は次の形。id/categoryは個人名やファイル名を含まない安全な識別子にする。

```json
{"id":"P001","category":"credential_example","expect":"detect","parts":["password = ","synthetic-value"]}
{"id":"N001","category":"benign_business","expect":"clean","text":"公開済みの紹介文を推敲してください。"}
```

- 必須: id/category/expectと、textまたはpartsのどちらか一方
- expectはdetectまたはcleanのみ。IDは全件で一意
- id/categoryは英数字で始め、英数字・下線・ドット・コロン・ハイフンの80文字以内
- 任意のnoteは文字列。これ以外のフィールド、重複JSONキー、空コーパスは拒否
- UTF-8、8MiB以下、1〜10,000件。1件のテキストは1〜65,536文字、partsは1〜64断片
- カスタム入力は常にcustom_unverified。ソフトウェアは合成/匿名化/共有権限を認証しない

v2レポートは入力の生バイトのSHA-256、実行日時、commitと作業差分有無を記録する。
本文・note・入力パスは記録しないが、カテゴリ・ケースID・ハッシュは含むため共有前に
確認する。保存は新規ファイルのみ、POSIXで0600、既存ファイルやリンクは上書きしない。
不正入力・保存失敗は終了コード2。片方のラベルしかなければ定義できない率はnull。
source_commit/source_dirtyが不明、または差分ありなら、固定revisionの証拠とは扱わない。

## 2. 許可が揃ってから顧客自身が低リスク入力で試す

合成評価の次に進めるのは、データ所有者が対象・端末・保存/削除・実施者を承認し、
必要な社内手続きとデータ取扱条件が揃った場合だけ。顧客所有の公開済み資料など、
秘密・個人情報を含まないと担当者が確認した10〜20件に限定する。
原本は顧客の端末から出さない。こちらへのアップロードやGitHubへの添付はしない。
機密・個人情報・実ログ・トークンが必要になったら停止し、別途明示的に判断する。

顧客本人が同じ資料について通常の目視確認とAISecureを使った確認を行い、
作業時間、誤検知、未検査、次の行動を理解できたかを記録する。
低リスクな陰性資料だけの試行から再現率や見逃し率を算出しない。
画面のnot_executedと外部送信なし、保存したinput_sha256と対象入力、
原本修正後に再検査が必要であることを実際に確認する。
画像/OCR非対応、PDFの非ページストリームやOfficeメタデータ等の未検査は
「問題なし」に読み替えず、担当者が扱えるかを受け入れ条件に含める。

## 3. 中止・復帰・受け入れ

意図しない外部接続、レポートへの本文混入、検査対象の取り違え、未検査を安全と誤解、
対応時間超過のどれかが起きたら利用を中止する。原本は変更しない。
Ctrl+Cでデモを終了し、端末上の一時鍵・履歴が消えたことを確認する。
ブラウザの入力/結果はリロードで消えるが、保存JSONは残る。
保存JSONと合成コーパスは合意した保持期限・顧客の削除手順で扱う。
ソフトウェア削除だけで保存物が消えた、または安全消去されたとは主張しない。
既存業務・既存保護製品に戻せることを担当者が確認する。

受け入れ記録は次を区別する。

1. 合成評価完了: revision・コーパスSHA・カテゴリ別の分母と結果・未達・工数
2. 顧客ローカル試用完了: 顧客側で実施した業務・期間・使用回数・担当者の確認
3. 導入実績: 合意した業務で実際に継続利用され、責任者が範囲を承認した記録
4. 有償実績: 契約と入金を別途確認。デモ・CI成功・口頭の興味を売上に数えない

公開事例・社名・コメント・画面の掲載には、内容と公開先を示した別の許可が必要。
この手順の存在だけで、顧客・導入実績・本番リリースの証拠が成立することはない。
