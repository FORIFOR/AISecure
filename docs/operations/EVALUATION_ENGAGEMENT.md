# 見逃し率の測定支援 — 相談できる範囲

作成日: 2026-09-22。状態: **開発版の評価支援。製品導入やSLAの提供ではない。**

`docs/security/DETECTION_MEASUREMENT.md` で、私たちは自分のツールの再現率が
**0.30**（陽性40件中28件を見逃し）であることを公開している。同種のツールで
この数字を出している例は、調べた範囲では見つからなかった。

この文書は「では自社の文書ではどうなのか」を知りたい場合に、何を頼めて、
何が頼めないかを先に書いたものである。

## 対象になる業務

AIサービス（ChatGPT・Claude・Gemini等）へ業務文書やテキストを貼る運用があり、
**「どれだけ止められているか」を誰も測っていない**状態にある組織。

情報システム部門・セキュリティ担当者を想定している。すでに商用DLPを導入済みでも、
その製品の見逃し率が非公開なら、同じ測定を並べて比べる用途がある。

## 提供できるもの

| 提供物 | 内容 |
|---|---|
| ラベル付きコーパス | 自社で実際に扱う情報の型（社員番号、取引先コード、帳票番号など）に合わせた**合成**データ。陽性・陰性の両方、および紛らわしい陰性を含む |
| 測定レポート | `tools/measure_detection.py` による再現率・適合率・誤検知率と、**1件も検出できなかったカテゴリの一覧** |
| 検知パターンの追加 | 測定で0件だったカテゴリのうち、パターンで拾えるものの実装（例: マイナンバーのチェックディジット、Luhn検証つきカード番号、日本語ラベルの鍵） |
| 再測定 | 追加実装の前後を同じコーパスで比較 |
| ローカル導入手順 | 自社環境での起動確認まで |

## 必要な条件

- 評価には**合成データまたは匿名化済みデータ**を使う。実データの受領は前提にしない。
- 実行環境: Python 3.11 以上。ローカルで完結し、外部送信はしない。
- 測定コードとコーパス形式は公開済みのものを使う。ブラックボックスの採点はしない。

## 検証方法

公開している `tools/measure_detection.py` をそのまま使う。コーパスと結果は
そちらの手元に残り、同じコマンドでいつでも再現できる。

```sh
python -m tools.measure_detection --corpus <自社コーパス> --out report.json
```

数字は合成コーパスに対する値であって、実運用の見逃し率ではない。
この区別は測定レポートにも明記する。

## 提供できないもの

以下は実装されていないか、検証されていない。**依頼を受けない範囲**として先に書く。

- 端末全体のDLP、USB・別アプリ・別ブラウザの制御
- 画像・スクリーンショットの中身の検出（OCRなし）
- ブラウザ内の停止の**保証**。拡張は best effort で、無効化・別ブラウザ・
  XHR/WebSocket は塞げない（`docs/operations/BROWSER_ENFORCEMENT.md`）
- 悪意ある内部者への対策（`docs/security/THREAT_MODEL.md` の A3 は設計上の非目標）
- 実機VPNの封じ込め・復旧、組織SSO/RBAC
- 第三者によるセキュリティ監査、認証、本番SLA、24時間対応

**価格・納期・契約条件・対応時間はここでは確約しない。** 範囲が決まってから個別に相談する。
