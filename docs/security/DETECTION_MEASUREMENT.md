# 検知性能の測定 — 2026-09-22

対象: `aisecure/preflight.py` の `SECRET` / `PERSONAL`（NFKC正規化後に照合）。
コーパス: [corpus.jsonl](corpus.jsonl) 60件（陽性40・陰性20）。
再現: `python -m tools.measure_detection --out docs/security/detection-measurement.json`
結果: [detection-measurement.json](detection-measurement.json)

## 前提 — この数字が意味しないこと

**コーパスは合成であり、我々自身が書いた。** したがってここでの再現率は
「我々が想定した漏れ方に対する値」であって、実際の業務文書の分布に対する値ではない。
実データによる測定は権限と対象データがないため **BLOCKED** のままである
（`docs/quality/claims.md` と同じ扱い）。

それでも測る理由は2つある。回帰の基準になること、そして
**「どのカテゴリを1件も検出できないか」は合成コーパスでも正しく分かる**ことである。

## 結果

| 指標 | 値 |
|---|---|
| 再現率（陽性40件） | **0.30**（12件検出 / 28件見逃し） |
| 適合率 | 0.857 |
| 誤検知率（陰性20件） | 0.10（2件） |

### 検出できたカテゴリ

AWSアクセスキー（2/2）、GitHubトークン（1/1）、PEM秘密鍵（1/1）、
`api_key:` / `password =` 形式（2/2）、メールアドレス（2/2）、
携帯番号（2/2）、全角化された鍵（1/1）。

### 1件も検出できなかったカテゴリ

| 分類 | カテゴリ |
|---|---|
| 認証情報 | Slack `xoxb-`、Google `AIza`、Stripe `sk_live_`、OpenAI `sk-proj-`、JWT、Azure 接続文字列、**日本語ラベル（「パスワードは〜です」「秘密鍵は〜になります」）** |
| 個人情報 | **マイナンバー**、**クレジットカード番号**、**固定電話**、住所＋氏名、生年月日＋氏名、パスポート番号、銀行口座、健康保険証番号、社員番号＋氏名 |
| 回避 | ゼロ幅文字、空白挿入、同形字、分割、Base64、`(at)` 表記、かな表記 |

日本語ラベル（`credential_kv_ja`）が0/2なのが構造的な問題である。
`SECRET` の鍵値パターンは `api[_-]?key|password|secret|access[_-]?token` の英語ラベルに
`:` または `=` が続く形しか見ない。日本の業務文書で最も多い
「パスワードは ○○ です」は対象外になる。

### 偶然の検出

`postgres://admin:S3cretPassw0rd@db.internal.example:5432/prod` は検出されたが、
**秘密情報としてではなく、メールアドレスのパターンに一致したため**である
（`SECRET` は一致せず `PII` のみ）。接続文字列の検知は実装されていない。
この種の「たまたま当たった」検出を能力として数えてはいけない。

### 誤検知2件

| ID | 入力 | 判定 |
|---|---|---|
| N11 | 説明目的の `user@example.invalid` | 検出。**妥当な誤検知**（形式としては本物と区別できない） |
| N18 | 製品型番 `090-1234-5678-A` | 検出。**妥当な誤検知**（携帯番号と同じ並び） |

どちらも review 止まりで上書き可能なため、業務への影響は「一手間」である。
誤検知率より見逃し率のほうが桁違いに深刻、というのがこの測定の結論である。

## 次に何をすると数字が変わるか

1. **日本語ラベルの鍵値検出**（「パスワードは」「秘密鍵は」「トークンは」）。
   `credential_kv_ja` 2件が拾える。実装コストは最も小さい。
2. **日本の個人情報パターン**（マイナンバーのチェックディジット、Luhn検証つき
   クレジットカード番号、固定電話）。陽性8件が拾える。
   チェックディジット検証を入れれば N06/N08 のような数値列での誤検知を避けられる。
3. **主要ベンダーのトークン形式**（Slack・Google・Stripe・OpenAI・JWT・Azure）。陽性6件。
4. 回避耐性（ゼロ幅文字の除去、区切り文字の正規化）。ただし
   **回避は A3 の領域であり、設計上の非目標**（`THREAT_MODEL.md` §2）。
   1〜3を終えてから、どこまでやるかを決める。

1〜3を実装すれば、このコーパスに対する再現率は 0.30 → 0.75 前後になる見込みである。
ただし**それは同じコーパスに対する値であり、実データの測定ではない。**
コーパスに追記して数字を上げる行為には意味がない。

## 変更していないこと

この測定では検知パターンを一切変更していない。数値は現行実装の実測である。
