# 脅威モデル — AISecure 0.4.0a3.dev0

作成日: 2026-09-22。対象: `26002d8` + 未コミット作業ツリー。
状態: **開発者プレビュー。本番防御として完成していない。**

この文書は「何から守るのか」を先に確定させるためのものである。
`docs/operations/CONTROL_SCOPE.md` が機能ごとの完了条件を列挙するのに対し、
ここでは攻撃者像・信頼境界・残存リスクを定義する。
実装の主張は本文中の測定またはコード位置で裏付ける。推測は「未測定」と書く。

---

## 1. 守る資産

| ID | 資産 | 損失の形 |
|---|---|---|
| AS-1 | 業務文書・テキストに含まれる機密情報 | 外部AIサービスへ渡り、学習・保持・第三者閲覧の対象になる |
| AS-2 | 認証情報（APIキー、秘密鍵、トークン） | 渡った時点で悪用可能。取り消しコストが発生する |
| AS-3 | 個人情報 | 法令・契約上の通知義務が発生する |
| AS-4 | 判断の証跡（誰が何を送ろうとし、なぜ止まったか） | 事後の説明責任が果たせない |
| AS-5 | 検査そのものの完全性 | 検査を回避・無効化されれば、他のすべての主張が崩れる |

AS-5 を最後に置いたのは順位ではない。**検査を迂回できる限り、AS-1〜AS-4 の保護は
「利用者が協力する場合に限る」という条件付きになる。** 現状はこの条件付きである。

## 2. 攻撃者クラスと、今日の適用範囲

| ID | 攻撃者 | 動機・能力 | 現状の扱い |
|---|---|---|---|
| A1 | 不注意な正規利用者 | 悪意なし。便利だから貼り付ける。検査に協力する意思はある | **対象。部分的に緩和** |
| A2 | 手順を省略する正規利用者 | 悪意なし。急いでいる。検査画面を開かない | **対象。部分的に緩和**（§4 T-4） |
| A3 | 悪意ある内部者 | 持ち出す意図がある。検査を避ける、加工する、別経路を使う | **対象外。防げない**（§4 T-5） |
| A4 | 侵害された端末・マルウェア | 利用者権限でプロセス・設定・拡張機能を変更できる | **対象外。信頼境界の外** |
| A5 | 外部AIサービス側・経路上の攻撃者 | 送信後のデータを扱う。応答に指示を混入する | **部分的に対象**（送信先固定・応答に実行権限なし） |

**今日の製品が成立する前提は A1 と A2 のみである。** A3 を防ぐと書いた資料・画面は
存在させない（`CONTROL_SCOPE.md`「絶対に表示しない完了表現」と整合）。

## 3. 信頼境界と入口

```
[利用者の入力] ──┬─→ ① 制御ワークベンチ（ローカルHTTP, 明示的に開く）
                 ├─→ ② aisecure-inspect / Python API（明示的に呼ぶ）
                 ├─→ ③ ブラウザ拡張ポップアップ（明示的に開く）→ Native Messaging → 同じScanner
                 └─→ ④ ブラウザでAIサイトへ直接貼り付け ──→ 拡張が fetch を包んで検査
                                                                     ↓
                                                              外部AIサービス
```

- 境界1: 利用者 ↔ 検査サービス。入口①〜③は利用者が明示的に選ぶ。入口④は
  対象4ホストに限り拡張が `window.fetch` を包んで自動的に検査する
  （`docs/operations/BROWSER_ENFORCEMENT.md`）。**ただしラッパーはページと同じ
  MAIN world にあり、拡張の無効化・別ブラウザ・XHR/WebSocket・iframe は塞げない。**
  A1/A2 に対する緩和であって、A3/A4 に対する境界ではない。
- 境界2: 検査サービス ↔ ポリシー・分類。`policy.json` と管理者署名の分類証明は
  管理者が持つ。利用者・モデルの自己申告 (`approved`, `data_class`) は採用しない
  （`aisecure/preflight.py:evaluate`）。
- 境界3: 検査サービス ↔ 外部送信。`guarded_call()` は allow 以外で通信処理を呼ばない。
  送信先は固定URL完全一致。部分一致・リダイレクト追従はしない。
- 境界4: 監査。本文を保存せず、HMAC仮名化 + AES-GCM + 連鎖チェックポイント。
  **鍵は環境変数由来であり、鍵の配布・失効・WORM保管は未実装。**

## 4. 脅威一覧

判定は 緩和 / 部分 / **未対応** の3段階。「部分」は条件付きでしか成立しない意味。

| ID | 脅威 | 現状の実装 | 判定 |
|---|---|---|---|
| T-1 | 機密文書をそのままAIへ添付する | xlsx/pptx/pdf の全XML・非表示シート・ノート・マクロ・埋め込みOLE・復号不能部を検査し、読めなかった部分は「読めない」として review/block に倒す（`documents.py`） | 部分（入口①〜③経由のみ） |
| T-2 | 認証情報を貼り付ける | `SECRET` 4パターン。NFKC正規化後に照合 | 部分（§5で実測） |
| T-3 | 個人情報を貼り付ける | `PERSONAL` 2パターン（メール、日本の携帯番号） | 部分（§5で実測） |
| T-4 | 検査画面を開かずにAIサイトへ直接貼る | 対象4ホストで `window.fetch` を包み、40文字以上の本文を検査。block は上書き不可、検査サービス不達も停止（fail closed）| 部分（A1/A2のみ。§7の条件付き）|
| T-5 | 検知を意図的に回避する（分割・符号化・画像化・言い換え） | なし。パターン照合のみ | **未対応**（A3のため設計上の非目標） |
| T-6 | 画像・スクリーンショットに含まれる機密 | OCRなし。`DOC-IMAGE-UNINSPECTED` として review に倒すのみ | 部分（検出せず、未検査と申告する） |
| T-7 | 文書内のプロンプトインジェクション | `DOC-INJECTION` で review。実行はしない | 部分 |
| T-8 | 同じ内容の二重送信・再送 | 耐久的な予約/確定とフィンガープリント。不明応答は自動再送しない | 緩和 |
| T-9 | 証跡の改ざん・消去 | 連鎖チェックポイント + 暗号化。**独立保管・WORM・鍵ライフサイクルは未実装** | 部分 |
| T-10 | 証跡から本文が漏れる | 本文・質問・トークンを監査に入れない（回帰テストあり） | 緩和 |
| T-11 | プレビュー機能からの漏えい | 秘密・個人情報を検出した文書は**本文全体を非表示**にする（部分伏せ字の保証が不可能なため）| 緩和 |
| T-12 | 悪意あるファイルで検査器を落とす／情報を取る | 展開量・深さ・XXE・資源・期限の境界、隔離ワーカー | 部分（隔離イメージの実ビルドは未実施） |
| T-13 | 送信先のすり替え | 固定URL完全一致、署名済み分類証明が資料・質問・送信先に結合 | 緩和 |
| T-14 | AIの応答に従って別の操作が実行される | モデルに実行権限なし。`agent.execute/delete/share/send` は常に保留 | 緩和 |
| T-15 | VPN経由の侵入後、機密へ到達する | 特権認証→機密アクセスの相関検知 | 部分（実ログ未評価） |
| T-16 | VPNの封じ込め | 登録acceptルールの状態変更、二者署名、STOP、再送防止 | **未対応**（設定変更≠封じ込め。実機未検証） |
| T-17 | 端末全体のDLP（USB・別アプリ・別ブラウザ） | なし | **未対応**（非目標） |

## 5. 検知境界の実測（2026-09-22）

`aisecure/preflight.py` の `SECRET` / `PERSONAL` に、NFKC正規化を通して
ラベル付きコーパス60件（陽性40・陰性20）を入力した結果。
再現は `python -m tools.measure_detection`、詳細は
[DETECTION_MEASUREMENT.md](DETECTION_MEASUREMENT.md)。

**陽性40件のうち検出できたのは12件（再現率 0.30）。適合率 0.857、誤検知率 0.10。**

| 分類 | 検出 | 未検出 |
|---|---|---|
| 秘密情報 | AWSアクセスキー（素・全角）、GitHubトークン、PEM秘密鍵、`api_key:` / `password =` 形式 | Slack `xoxb-`、Google `AIza`、Stripe `sk_live_`、OpenAI `sk-proj-`、JWT、Azure接続文字列、日本語ラベル（「パスワードは〜です」） |
| 個人情報 | メール、携帯番号 `0[789]0-` | 固定電話、マイナンバー、クレジットカード番号、住所＋氏名、生年月日＋氏名、パスポート番号、健康保険証番号、銀行口座、社員番号、`(at)` 表記のメール |
| 回避 | 全角は正規化で吸収される | ゼロ幅文字、空白挿入、同形字、分割、Base64、かな表記 |

読み取るべき結論は3つある。

1. **全角化では回避できない**（NFKC正規化が効く）。一方、ゼロ幅文字1つで回避できる。
2. **日本企業の機密として最も一般的な項目——マイナンバー、クレジットカード、
   固定電話、住所氏名、口座情報——は1件も検出しない。** 現状の `PERSONAL` は
   「メールアドレスと携帯番号の検出器」であり、個人情報検出器ではない。
3. DB接続文字列が検出されたのは秘密情報としてではなく、**メールアドレスの
   パターンに偶然一致したため**である。偶然の一致を能力として数えない。

したがって **「検出なし」は安全の根拠にならない**。この主張は画面・API・CLI の
いずれにも出しておらず（`no_findings` は常に `release_authorized: false` を伴う）、
今後も出さない。

コーパスは合成であり、**実運用の見逃し率ではない**。実データでの測定は
対象データと権限がないため BLOCKED のままである。

## 6. 残存リスク（受け入れている前提）

- R-1: 入口④は `window.fetch` のみを覆う。XHR・sendBeacon・WebSocket・
  Service Worker・クロスオリジン iframe・別ブラウザ・拡張の無効化は残っている。
  実運用での保護率は**未測定**である。
- R-2: 検知パターンが §5 の範囲にとどまる限り、T-2/T-3 の緩和は「代表的な2〜3種」
  に限られる。
- R-3: 監査鍵が環境変数にあり、端末を取れる攻撃者（A4）は証跡を再生成できる。
- R-4: 第三者によるコードレビュー・侵入試験を受けていない。
- R-5: 本作業ツリーはCI未実行。単一環境の実行結果しかない
  （過去に「121件成功」と記録されたテストが別環境で37件失敗した前例がある）。

## 7. 判定を上げてよい条件

| 現在の主張 | 上げられる主張 | 必要な証拠 |
|---|---|---|
| A2 に対し fetch 経路を停止できる | **A2 に対して一般に有効** | XHR/sendBeacon/WebSocket/iframe の網羅と、迂回条件を明記した実運用測定 |
| 代表的なパターンを検出する | **実運用の見逃し率が既知** | ラベル付きコーパスでの再現率・誤検知率の実測 |
| ローカル試験済み | **多環境で再現する** | CIの全マトリクス実行とリリースゲート通過 |
| 内部レビュー済み | **外部レビュー済み** | 第三者のコードレビューと侵入試験の報告書 |
| 設定変更できる | **封じ込めできる** | 実機での到達性試験（既存接続・HA・IPv6・フォールスルー） |

このどれも満たしていない項目については、画面・README・公開サイトで
達成表現を使わない。
