# 検証結果 — AI Secure v0.1.0

実施日: 2026年9月12日

## 結果

**Pythonの自動テスト80件が通過**しました。実行環境はLinux、Python 3.13.5。最終確認時のunittest所要時間は約0.84秒ですが、これはテストスイートの時間であり、実ログの処理速度や検知遅延のベンチマークではありません。

```text
python3 -m unittest discover -s tests -v
Ran 80 tests
OK
```

JavaScriptはNode.js v22.16.0の `node --check web/app.js` で構文検査を実施しました。実アプリはNode.jsを必要としません。

## 自動テストの範囲

| 分野 | 主な検証 |
|---|---|
| 優先度 | Medium相当でも公開・特権・機密への到達性が重なるとP1。非公開・修正済み・不明情報を区別 |
| 相関 | 同一ユーザー・セッション、ログイン前後関係、30分の関連付け上限、機密ラベルの有無 |
| 大量参照 | 異なるファイル数、イベント重複、同一ファイル再参照、99件/100件境界、低速な参照を対象外として扱う |
| 正常・不明 | 正常な認証、失敗した認証、信頼度不明、正規のバックアップでも大量参照には該当し得ること |
| 入力 | タイムゾーン、未来時刻、無効CVSS、真偽値の型、未定義フィールド、参照先不在、2 MiB・5,000件制限 |
| 仮名化 | 名前空間・鍵の分離、生のユーザー・セッション・ファイル識別子を永続化しない |
| 対応 | 承認必須、確認文字列、理由、期限切れ、入力更新、二重・同時承認の拒否、実行しない結果表示 |
| 改変検出 | スナップショット本文、対応計画本文、監査ログ変更の検出。末尾削除には外部チェックポイントが必要であること |
| LLM | 既定の非LLM表示、未接続フォールバック、クラウド名拒否、出力スキーマ、架空の参照ID、ツール呼出拒否 |
| HTTP | Bearer認証、Host/Origin/CORS、Content-Type、トラバーサル拒否、秘密ファイルを配信しない、ヘッダー、計画から承認までのAPI連携 |

LLMのテストはモック応答です。実際のモデルの品質・日本語能力・安全性・遅延を測ったものではありません。

## ブラウザ表示の確認

Chromium + Playwrightによる **オフラインのDOM描画** で確認しました。実行環境の管理ブラウザはlocalhostへの直接ナビゲーションを `ERR_BLOCKED_BY_ADMINISTRATOR` で拒否したため、その制限は変更せず、同じHTML/CSS/JSに読み取り専用の合成状態を埋め込んで表示を検証しました。HTTP APIは、別途上記テストで本物のローカルHTTPサーバーを起動して確認しています。

確認できた範囲:

- デスクトップ 1512×1080 の概要表示と全体スクリーンショット。
- スマートフォン幅 390×844 で横方向のはみ出しがないこと。実iPhone/Safariでの試験ではありません。
- 概要、資産、計画、監査、設計の各画面の切り替え。
- 読み取り専用プレビューでは書き込みボタンを無効化。
- 上記範囲でJavaScriptの実行時エラーなし。

**本番と同じブラウザ通信経路でのE2E試験、CSPと実画面操作を一体にしたE2E試験、Safari・Firefox・Windows・macOSでの動作は未検証**です。スクリーンショットは同梱の `docs/screenshots/` を参照してください。

## 未検証・未測定

実VPN、IdP、ファイルサーバー、実モデル、クラウド、複数管理者、マルチテナント、実機の停止・失効・復旧、大規模ログ、長期運用、侵害されたホスト、外部監査保管、保持期限・削除ポリシーは未検証または未実装です。

合成シナリオで条件が正しく動くことと、現実の侵害を検出できることは異なります。検知率、誤検知率、初動時間短縮、漏えい防止の効果、セキュリティ認証取得を確認したものではありません。出荷や顧客導入には `SECURITY.md` の本番化ゲートが必要です。
