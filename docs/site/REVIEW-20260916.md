## 再評価

検証用OSSとして、決定論的な検査、拒否時に通信処理を呼ばない部品、証拠と仮説の区別は実装されています。一方、「導入すれば最新AIの利用や組織全体を守る製品」という要件にはまだ達していません。現在の最大の不足はモデルの選定ではなく、信頼された入力・迂回できない実行経路・実機との接続です。

|---|---|---|

`public` などの分類や `agent.read` という操作種別を、モデルに自己申告させて信頼してはいけません。アダプターとポリシーを管理し、検査に失敗したときに直接通信へフォールバックしないことが必要です。ガードは一般的なプロンプトインジェクション検出器ではなく、全秘密情報・画像・PDF・分割や符号化された情報を網羅しません。

コード統合、合成データのテスト成功、ホームページ公開を、本番防御の有効化や第三者監査と同一視しません。事件別の要求仕様は [PREVENTION_BOUNDARY.ja.md](../PREVENTION_BOUNDARY.ja.md) を参照してください。

## ホームページの通信と問い合わせ

旧 `portfolio.js` は、リンククリックや動画再生等のイベント名・製品識別子・言語をアクセス計測先へ送っていました。これは企業の生ログの送信とは別です。

新しい日本語・英語トップページには `data-analytics="off"` を指定し、共通スクリプトがイベント送信前に終了するよう変更しました。他のページまで一律に無通信とする変更ではありません。ページ・画像・動画の配信通信、利用者がリンク先を開く通信は発生します。

問い合わせの既存送信先、入力契約、同意欄、取り扱い説明は維持しました。トップページのフォームは `method="post"` とし、送信ボタンを初期状態で無効にして、JavaScriptの送信処理が登録された後だけ有効化します。JavaScriptの初期化失敗時に問い合わせ内容が既定のGETでURLに入る経路を避けるためです。今回、問い合わせサービスの保存・削除処理は独立に検証していません。
